# SpaceTabs presentation storyboard

Original draft: 12 shots, approximately 70 seconds. The SVGs and contact sheet preserve the initial schematic proposal. The current animation restores this demonstration sequence inside a 27-inch macOS monitor, with colored zone borders, dark independent tab panels, native app-window controls, and a branded opening; see [Presentation video](VIDEO.md) for the renderer and review frames.

Orange = A, blue = B, green = C. Keep the camera fixed so viewers can follow what changes. Assign two windows slowly, accelerate the remaining assignments, and pause for the key demonstrations. Frame 11 shows the three planned shortcut beats together; the video would present one at a time.

## 01 · 00–05s · Too many windows

“I’d like a more organized desktop.”

Overlapping windows slide in. Pause briefly on the clutter, then introduce the thought.

## 02 · 05–10s · Start with a little structure

“A place for every window.”

Fade to an empty desktop. Reveal only the two tab bars; no app windows are assigned yet.

## 03 · 10–15s · Choose your layout

“Arrange it your way.”

Morph Two columns into Split left. Keep the camera still; show A and C beside the larger B.

## 04 · 15–21s · Assign the first app

“Your browser, right here.”

Slowly Control + right-drag Browser into B. Show the preview outline, release, then settle into place.

## 05 · 21–27s · Give another app its place

“Your notes, beside your work.”

Repeat slowly with Notes into A. Leave Browser in B so the independence is already clear.

## 06 · 27–31s · Build up the workspace

“More apps. The same clear desktop.”

Speed up: Editor and Preview join B, Finder joins A, Terminal and Messages join C. Tabs accumulate.

## 07 · 31–37s · Switch one group at a time

“Change one space. Keep the rest.”

Click Browser in B, then Editor. Only B changes; Notes in A and Terminal in C stay selected.

## 08 · 37–43s · Keep your Mac workflow

“Your usual app switching still works.”

Use Command-Tab normally, then choose SpaceTabs to restore the selected workspace. Settings stays closed for this shot.

## 09 · 43–49s · Let the bars get out of the way

“Prefer your tab bars out of sight?”

With auto-hide enabled, fade the bars out and let windows fill their zones. Control + Option + Command briefly reveals the bars.

## 10 · 49–56s · Drag from anywhere in a window

“Hold Control. Right-drag. Drop.”

Show the modifier and right mouse button. A ghost outline follows Preview to C; the real window moves only on release.

## 11 · 56–66s · A few shortcuts worth remembering

“Less reaching. More doing.”

Three short beats: focus B, switch its tab, then zoom and restore the focused window. Show one key combination at a time.

## 12 · 66–70s · The organized desktop

“Your windows. Your zones. One desktop.”

Return to the finished workspace. Hold the SpaceTabs name and tagline for the final four seconds.

## Accuracy notes

The scene labels are editorial captions, not proposed UI text. The assignment scenes use the existing optional Control + right-drag gesture, enabled in advance. Show only the preview outline during the drag; move the actual window on valid release. Releasing Control first cancels assignment.

Auto-hide is enabled in the hidden-bars scene. Control + Option + Command reveals bars temporarily; it is not a hide/show toggle. The keyboard montage uses the default focus-B, next-tab, and zoom/restore shortcuts. Standard Command-Tab still switches between real apps; selecting SpaceTabs restores the workspace. Keep Settings closed for that demonstration.

The storyboard uses schematic drawings rather than realistic app screenshots. An animated version can now be rendered locally; see [Presentation video](VIDEO.md). No app settings or running windows were changed while preparing these artifacts.
